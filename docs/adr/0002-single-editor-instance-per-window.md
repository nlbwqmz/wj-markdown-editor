# 切换标签页复用同一个编辑器实例

一个窗口内切换标签页时，复用同一个 CodeMirror `EditorView`，为每个文档会话保留一份 `EditorState`，通过换入换出切换；不为每个标签页创建独立的编辑器组件实例。

## Considered Options

- **每标签页一个编辑器组件实例**（`v-show` 保活）：切换瞬时、滚动位置天然隔离。但每个标签页要常驻一份编辑器 DOM 和一份预览（含 Mermaid 渲染），且侧边栏桥接、预览搜索桥、资源上下文菜单这些全局单例桥接会互相覆盖，必须改成"只有活动标签注册"——那就等于承认同一时刻只有一个活动编辑器，其唯一优势随之消失。
- **单实例 + 整篇替换 + 切换时清空 undo 历史**：改动最小，但"切走再切回不能撤销"，且跨标签撤销会退回到别的文档内容（既有缺陷）。

## Consequences

- 切标签的成本与今天"在当前窗口打开另一个文件"完全相同：一次全量解析 + 预览重渲染。
- undo 历史与光标选区按标签页隔离，这是选此方案的主要收益。
- 滚动位置仍走现有的按文档路径索引的锚点缓存，与 `EditorState` 是两套独立存储。
- 锚点缓存的生命周期跟随标签页，不设数量上限：标签关闭时删除该文档的桶。因为每个被打开过的文档必然对应一个标签页，桶数天然等于打开的标签数，不需要数量上限兜底。
