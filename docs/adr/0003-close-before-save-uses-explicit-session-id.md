# 关闭前保存以显式 sessionId 为准，正文收敛不再由开关控制

`document.edit` 必须显式携带 `sessionId`（并带单调递增的 `seq`），主进程只按它定位会话；关闭任何标签页或窗口之前，渲染层必须先把目标会话的当前正文收敛进主进程。自动保存开关只决定「是否写盘」，不再决定「是否同步正文」。

## Context

自动保存最初只有 `blur` / `switch` / `close` 三个触发器，而「关标签」被明确排除在外，理由写在命令层注释里：静默写盘比弹一次确认更危险。

新增 `closeTab` 触发器要求「关标签即保存」，这条需求直接压在一个更早的缺陷上：`document.edit` 不携带会话身份，主进程一律把它写到窗口的**活动会话**。于是每次切标签都可能把后台标签的正文丢掉（只有活动会话的正文会被同步），后果有三层：

1. 后台标签的会话正文可能落后任意长度的连续输入；
2. 落后到「会话内容恰好等于磁盘内容」时，脏判定失效，关标签会静默关闭并丢掉输入；
3. 仍然判脏时，关闭流程会激活该标签并用会话旧内容覆写编辑器视图，用户在弹窗里确认保存，写下去的是旧内容。

只要「正文归属靠活动会话」这条隐含契约还在，任何「关闭时自动保存」都只是把一个已知会写错内容的动作自动化。

## Considered Options

- **关闭前强制激活目标标签再保存**：改动最小，但界面会一路跳标签；且保存失败中止后，用户面对的是已经被打乱的视图。更重要的是：只要还有一处保存路径按「活动会话」取正文，循环激活就会把 A 标签的正文写进 B 标签的文件。
- **让 `closeTab` 隐含启用 `switch` 的 flush 行为**：等于把一个开关的语义偷渡给另一个开关，用户勾了「关闭标签时」却顺带改变了切标签行为，无从理解。
- **正文收敛无条件执行（已采纳）**：flush 属于正确性，不属于用户偏好。开关只保留「是否写盘」这一个含义。

## Consequences

- `document.edit` 的 `sessionId` 是必填项，主进程校验归属窗口，缺失或越权直接拒绝；不留「缺省回退到活动会话」的兼容分支。
- `seq` 用于丢弃并发下的过期写入：关闭链路会集中 flush 多个会话的全文，没有序号就会出现旧正文盖回新正文。
- `seq` 的生命周期跟随**会话销毁**，不跟随「关闭命令被受理」：脏标签会先进确认流程，用户取消后仍要继续编辑。一旦在受理时就归零，后续编辑会以更小的序号到达并被全部丢弃，表现是「取消关闭后继续输入，输入立刻消失」。同理，标签迁移到新窗口时必须把会话侧的 `editSeq` 归零，因为序号权威换到了另一个渲染进程。
- 保存回流（`save.started` / `save.succeeded` / `save.failed` / `watch.bound`）与 watcher 重绑定全部按 `job.sessionId` 定向，避免结算到活动会话。
- 关窗口必须先向渲染层发起 flush 请求并等待 ack，再进入保存裁决。这条反向链路是新增的失败面：用 `render-process-gone` / `unresponsive` / `destroyed` 释放等待，**不使用定时器**；超时降级不在本决策范围内。
- 批量关闭与关窗口的保存路径**禁止调用 `activate-tab`**。批量关闭完成后 `activeSessionId` 必须与操作前完全一致，这是可自动断言的不变量。
- 无法自动保存的四类情形有明确出口：`recent-missing` 直接放行关闭；未命名草稿、未决外部变更、写盘失败则「关标签跳过并保留、关窗口整窗中止回落到未保存确认弹窗」。
- 未启用 `closeTab` 时，批量关闭仍只关干净标签、不提示、不保存——开关关闭即行为与旧版一致。
- 本决策描述的是正文归属与关闭时序；标签页与编辑器实例的从属关系见 ADR 0002（注意该文档描述的是早期的单实例方案，当前实现为每标签一个 `EditorView`，见 `useEditorCore.js` 顶部注释）。
